# Security update review — October 18, 2026

## Decision and scope

Replace PR #1's Next.js 14.2.35 target with **15.5.28**, resolving Sharp to **0.35.5** and overriding all PostCSS instances to **8.5.30**. This is a focused framework remediation, not certification that the entire application is free of vulnerabilities. The remaining dependency findings below require separate remediation.

The review baseline is main commit `ea4844ddbc3921ef7dd045bfecddc63225582ca2`; the original PR head was `b2545d3f638678b617396ebc7636c44a804fafe8`. PR #1 was open and draft. Its Vercel and Netlify preview statuses were successful, but dated February 13, 2026. No GitHub Actions PR workflow runs or automated unit/integration test script were present.

React and React DOM retain their existing 18.3.1 resolution, which satisfies the published 15.5.28 package peer ranges. No direct react-server-dom dependency exists. Next.js supplies its bundled RSC implementation. Three server pages now await `cookies()` for the Next.js 15 request API.

All former `latest` manifest entries are pinned to their original main-branch lockfile versions. Supabase, Recharts, Radix Progress, date-fns, and Sonner retain those original versions rather than including unrelated upgrades from the bot's lockfile or registry tags. The lockfile is generated by pnpm, including native package integrity records; it is not manually edited.

## Validation

- Node 24.19.0 / pnpm 11.25.0.
- `pnpm install --frozen-lockfile --ignore-scripts`: passed. Installation scripts were disabled during local validation.
- `pnpm build`: passed with dummy loopback Supabase configuration, without production credentials or database access.
- `node scripts/security-smoke.mjs`: 18 HTTP checks passed for public login/signup and unauthenticated dashboard, reports, templates, and notifications routes. Both forged `x-middleware-subrequest` and `x-nextjs-data` requests retained the expected behavior.
- Standalone TypeScript check: **63 existing diagnostics on both main and the updated app, with identical diagnostic lines**. No added diagnostics in this comparison. The repository already sets `typescript.ignoreBuildErrors` and `eslint.ignoreDuringBuilds`, so a successful build does not imply successful type checking or linting.
- `pnpm lint`: unavailable as a completed check; the existing project has no ESLint configuration and prompts for setup. No configuration was introduced just to conceal this gap.
- Existing Supabase dependencies emit Edge Runtime warnings for Node version APIs. These dependencies were not upgraded in this focused update.
- `git diff --check`: passed.

The HTTP checks use dummy configuration and do not validate successful authenticated Supabase operations, role-specific access, session refresh, billing, receipt downloads, or browser navigation. They are regression smoke checks, not an exhaustive exploit test.

## Remaining audit findings

The baseline audit reported 102 findings (6 critical, 42 high, 45 moderate, 9 low). The updated lockfile audit reports **62 findings: 3 critical, 26 high, 28 moderate, 5 low**. No findings remain against Next.js, Sharp, PostCSS, or Nano ID in this audit. Finding counts describe package/advisory matches, not proven exploitable application paths.

| Remaining package | Advisory count | Follow-up |
| --- | ---: | --- |
| jsPDF | 10 | Includes critical local-file/path traversal and new-window HTML injection. The inspected receipt generator uses text drawing and `.save()`, not `.html()`, new-window `.output()` modes, or AcroForms. Upgrade to a patched 4.x version in a separately validated receipt/export change; do not assume all paths are unreachable merely from this inspection. |
| tar | 13 | Includes critical decompression/parse DoS. Present through Tailwind's build dependency chain. Update build tooling/transitives and validate native assets; do not feed untrusted archives to the affected parser. |
| DOMPurify | 19 | jsPDF optional HTML-rendering dependency. Update with the PDF dependency and test any HTML conversion use. |
| brace-expansion | 7 | Update affected build/tool dependency paths. |
| minimatch | 3 | Update affected dependency paths. |
| lodash | 3 | Validate patched version and audit template/prototype-mutating use. |
| ws | 2 | Supabase/ioredis dependency paths require an updated compatible version. |
| browserslist | 2 | Update build tooling and its data dependencies. |
| uuid | 1 | Update affected package chain. |
| fflate | 1 | Update PDF/archive-related chain. |

These remaining findings were already present on main and were not introduced by the framework update. `pnpm audit` still exits nonzero; this change must not be described as a clean whole-project security audit.

## Deployment requirements

1. Require fresh Vercel and Netlify results for the revised PR commit; the February statuses validate a different tree.
2. Use the committed pnpm lockfile and workspace override configuration. Confirm host Node/pnpm compatibility and retain Sharp 0.35.5 / PostCSS 8.5.30 in the installed dependency tree.
3. After merge, confirm production deployment of the merge commit on each active host and retire earlier vulnerable deployments/origins as appropriate. Purge affected CDN caches if a poisoned cache is suspected.
4. With a staging account, verify login/logout, expired-session refresh, role-based dashboard access, notifications, reports, billing, and PDF exports. No production credentials or patient records were used in this review.
5. Address the pre-existing TypeScript errors, configure linting, and remediate the remaining dependency findings. Continue checking vendor advisories; this review is dated October 18, 2026.
